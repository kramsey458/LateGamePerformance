Late Game Performance

Same decisions, sooner.

A Timberborn 1.1 mod for big colonies that stutter. It removes work the game repeats over and over, so you get fewer lag spikes and shorter freezes.

  • Your beavers decide exactly what they would anyway. Each speed-up gives the game's own answer, checked against the game's code.
  • Built for BeaverBuddies co-op. Nothing that affects the simulation is a setting, so every player on the same version runs the same code.
  • For big colonies. Hundreds of beavers late in a game. A small colony has little repeated work to remove.

Big colonies do the same work over and over.

Every hauler decision, finished road and lumberjack's search makes the game redo work whose answer mostly hasn't changed. In a small colony that costs nothing. With hundreds of beavers it adds up, and you feel it as stutter.

This mod keeps answers the game has already worked out, does heavy work on other CPU cores, and skips lookups that can't change the result. Beavers make the same choices, just sooner.

What it changes in your game

Six jobs the game repeats all the time, each done faster and the game's own way. Most can be checked against the game while you play.

The game's own tickSame order, same answers. The mod only shortens the work inside it.

Haulers stop redoing their homework

For every hauler looking for work, the game asks every building in the district for its jobs and sorts the list. The mod keeps each building's jobs until something changes, then sorts the list the game's way.

Road changes stall the game less

After a path, stair or platform is finished, the game rebuilds every building's route map on the main thread. The mod spreads that over up to 7 worker threads. The maps come out exactly as the game builds them.

Lumberjacks search smarter

To find a tree, the game measures the path to every marked tree, though most are still growing. The mod leaves out the measurements that can't change the answer. Lumberjacks, gatherers and farmers get the game's own result.

After a long frame, such as an autosave, the game crams what it missed into the next few frames. In a logged 354-beaver session, each hitch became about a second of stutter. The mod runs the same ticks, in the same order, over ordinary frames.

And the rest of the crew

Entities with nothing to tick skipped
The game visits ten thousand trees, crops and paths every tick, though they have nothing to do. The mod ticks only the ones that do, in the game's own order.
Beavers off the roads kept
A beaver in a field choosing where to eat or rest makes the game search the terrain again for every building it considers. The mod keeps up to 32 searches and continues them instead. The distances are the game's.
Plant water, soil and the water map other cores
Plant water levels, changed soil cells and the water map copy are worked out on worker threads.
District counts and homes kept
Each district's resource count and the every-tick search for a beaver to move into a home stop redoing unchanged work.
"Can a beaver reach that?" leaner
After a road change the game floods the whole walkable colony to answer this. The mod floods it the same way, without first resetting every tile of the map.
Terrain route maps other cores
Built on worker threads alongside the road ones, with the game's contents.
Per-frame chores less often
The audio listener, the alert lists, the selection panel, far and off-screen animation, the physics sync and water rendering stop redoing work every frame. None of it touches the simulation.
Timing lines in the log yours to read
Ticks per second, where the main thread's time goes, the longest frame, memory clean-ups and saves, so you can measure your own colony.

Built for BeaverBuddies co-op

In multiplayer every player's game must calculate exactly the same thing. A mod that changed even one answer would be worse than no mod. So keeping co-op games in step comes before every speed-up.

  • The game's own answers. Hauling lists, tree searches and route maps match the game's own. Tests compare them with the game's code.
  • Same version, same code. Nothing that affects the simulation is a setting, so two players can't drift apart by editing a settings file.
  • Never tied to one player's screen. Which route maps get built never depends on what a single player looked at.
  • Played in multiplayer on two computers, including a 35-minute session logged on both. Larger groups haven't been reported yet.

What may differ between players

Incremental garbage collection, thread counts, timing logs and the verify settings. They don't affect the simulation, so each player can choose them. Everything else needs the same mod version and the same game version, updated together.

What it always does

  • Can be checked against the game. The verify settings run the game's own code alongside and log any difference, without changing what the game is told.
  • Switches a feature off if it hits an error, and lets the game's own code run instead. A dialog then asks every co-op player to restart.
  • Leaves a feature off if a game update changed something it needs.
  • Stores nothing in your saves.

What it never does

  • Approximate. It skips work only when the answer cannot change.
  • Change what your beavers decide on purpose. The known difference is explained in the FAQ.
  • Touch a game file, unless you tick Incremental garbage collection.
  • Need anything besides Harmony and Mod Settings.

What is tested, and what isn't

Tested extensively, but still a young mod, so here is the honest picture. Try it on a copy of a save first.

Tested

In play

  • A late-game save of about 350 beavers: noticeably fewer lag spikes, then "working well" and "working amazingly well".
  • A 362-beaver colony with Verify every feature on: every verify setting reported 0 differences from the game's own code, including the save snapshot at an autosave.
  • Multiplayer on two computers, including a 35-minute session logged on both.

Against the game's code

  • 523 automated checks pass against the installed game's own assemblies, including 131 patch targets.
  • Rebuilt route maps are identical to the game's, node for node.
  • The tree and plant search gives the game's answer in 4,000 random forests.
  • The tick loop, saves, plant water, soil and the water map copy each match the game's own code.
  • Resumed terrain searches give the game's distance in every test.

Not yet

  • This release's numbers. It has been played, but the logs of that session haven't been read yet.
  • The frames that get slower each evening. They are still unexplained.
  • A verify session longer than about twenty minutes of play.
  • A before-and-after of each feature in the same save. The improvement is reported from play and logs.
  • A controlled frame-rate benchmark.
  • A co-op game where one player has the verify settings on and another has them off.
  • Groups larger than two players.
  • The main-menu notice about incremental collection, because the test computers already have it on.

Five minutes to install

  1. Harmony and Mod Settings from the Steam Workshop.
  2. The ZIP under Assets on the release page, not Source code, into Documents\Timberborn\Mods.
  3. Playing co-op? Every player installs the same version, and you update together.
